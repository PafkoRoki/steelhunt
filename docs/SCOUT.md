# Scout — automatic search (local)

`npm run scout` searches OLX.pl, Allegro Lokalnie, Sprzedajemy.pl, Kleinanzeigen.de and (official API, only when `EBAY_CLIENT_ID` / `EBAY_CLIENT_SECRET` are set — normally in GitHub Actions via `--only=ebay`) eBay.de for **retro MTB** and writes
`data/imports/auto-olx.json`, `auto-allegro-lokalnie.json`, `auto-sprzedajemy.json` and `auto-kleinanzeigen.json`. The normal ingestion
(`npm run ingest` / the "Ingest listings" workflow) then publishes them.

## How it accesses the portals

| Portal | Endpoint | Basis |
|---|---|---|
| OLX.pl | `https://www.olx.pl/api/v1/offers/` (category 767 Rowery, Poznań ± radius) | Explicitly `Allow`ed in olx.pl/robots.txt |
| Kleinanzeigen.de | Search pages `/s-fahrraeder/<query>/k0c217` + ad pages `/s-anzeige/...` | Not disallowed in kleinanzeigen.de/robots.txt |
| Allegro Lokalnie | Search pages `/oferty/rowery-i-akcesoria/rowery-16420/q/<query>` + ad pages `/oferta/...` | Only `/oferty/wystaw/` is disallowed. The portal rate-limits (HTTP 429): extra 8 s pause, 5 queries, skipped for the run on the first error |
| Sprzedajemy.pl | `/poznan?inp_text=<query>&inp_distance=150` + ad pages | Search and offer pages not disallowed |

- Honest User-Agent `steelhunt-scout/0.1 (...)`, a fixed delay between requests (`config/scout.json → delayMs`),
  at most ~30 requests per run, a cap on ad-page fetches. No login, no CAPTCHA solving, no proxies, no browser
  impersonation. If a portal starts refusing requests (e.g. HTTP 429), the run logs it and stops querying that portal until the next run — it does not try to get around it.
- **Runs only on the owner's computer** (scheduled Claude task), never in GitHub Actions.
- Portal terms of use may restrict automated access; this is a low-volume personal tool. The owner decides whether to run it.

## What is published

Title, price, location, date, link, up to 3 photo links (hotlinked from the portal's CDN) and a **fact summary**
generated by the analyzer (tubing, construction, fork, components, wheel size…). The seller's full description is
used for analysis in memory only and is never written to the repository.

## Filters

Kept: retro MTB/ATB, MTB frames. Dropped: road bikes, kids'/teen bikes, e-bikes, full suspension, single parts,
modern bikes (27.5"/29", disc/hydraulic brakes, carbon, production year ≥ 2005), listings without any retro signal.
A Shimano generation code up to 2002 (e.g. RD-M732) counts as a retro signal, as do Deore DX, STX and Exage
("Deore XT/LX" alone does not — those groups are still made).
Also dropped: titles with no bike word and no known maker (e.g. fishing rods), tandems, cross / trekking / 28" bikes,
single parts named by a part code ("FC-M900") or a fork brand ("Marzocchi Bomber") without a bike word,
found / stolen / wanted posts and listings priced at 0.
`npm run scout -- --refilter` re-applies the current filters to the saved `auto-*.json` files without fetching
(add `--dry` to only list what would be dropped).
Allegro Lokalnie: towns within 200 km of Poznań (unknown towns dropped). Sprzedajemy: the portal's own 150 km filter.
Kleinanzeigen: only postcode regions within driving range of Poznań (eastern Germany, see `postcodePrefixes`).
EUR prices are converted with the exchange rate from Settings (default 4.25).

Listings stay published for `keepDays` (14) after they were last seen in the results.

## Photo review (frame decals, component markings)

The scheduled scout task (Claude on the owner's computer) also looks at the listing photos:

1. `npm run photos -- todo --limit=10` picks listings whose photos were not checked yet, downloads up to 3
   photos each into `tmp/photo-cache/` (git-ignored, low rate, same User-Agent) and writes `tmp/photo-cache/todo.json`.
2. Claude views the photos and writes what is printed on the bike: frame brand/model decals, tubing decals
   (Tange, Columbus, Reynolds, Ishiwata…), component markings (Deore XT, RD-M735…). Each reading has
   `confidence`: `legible` (fully readable) or `probable` (partly readable). Nothing is guessed: unreadable
   decals are left out.
3. `npm run photos -- save <file.json>` validates the readings and merges them into `data/photo-notes.json`.

The ingestion attaches the notes to listings. **Only `legible` readings feed the analysis** (evidence
labelled “zdjęcie”); `probable` ones are shown on the listing page only.
